# Runforge

Интерфейс просмотра запусков AI-агентов. Данные приходят из локального Promise-сервиса
с задержкой 2 секунды; backend, авторизация и настоящие AI-модели не используются.

## Запуск

Требуется Node.js 22 (от 22.12), 24 или 26+ — см. engines в package.json.
Проверено на Node.js 24.21.0 и npm 11.19.0.

```sh
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://localhost:5173`.

## Возможности

- 8 запусков со всеми четырьмя статусами: Queued, Running, Succeeded, Failed.
- Поиск по названию и репозиторию без учёта регистра, совместный фильтр по статусу.
- Сортировка по дате создания или длительности в обоих направлениях.
  Неизвестная длительность всегда в конце; нулевая отображается как `0 с`.
- Модальные детали с метаданными, логами и результатом при его наличии.
  Открытие с клавиатуры, закрытие Escape, возврат фокуса к запуску.
- Загрузка, ошибка с повтором и пустой результат со сбросом условий.
- Восстановление условий из URL, поддержка перезагрузки и Back/Forward.
- Таблица на широком экране, карточки на узком; интерфейс от 360 px.

Интерфейс русский, статусы английские. Даты выводятся в часовом поясе браузера.
Запуски демонстрационные: статусы и длительность не обновляются по таймеру.

## URL-фильтры — бонус

```text
/?status=running&q=web&sort=duration-asc
```

`status`: queued / running / succeeded / failed; отсутствие означает «Все».
`q`: поисковая строка.
`sort`: created-desc (по умолчанию), created-asc, duration-desc, duration-asc.

Значения по умолчанию не загромождают URL. Неизвестные статус и сортировка читаются
как значения по умолчанию. Сторонние параметры и hash сохраняются.
Смена статуса или сортировки добавляет запись в историю; ввод поиска заменяет текущую
запись, чтобы Back не перебирал каждый символ. Сброс очищает поиск и статус,
сохраняя выбранную сортировку.

## Проверка ошибки mock API

Создайте `.env.local` в корне проекта:

```dotenv
VITE_MOCK_FAIL_ONCE=true
```

Перезапустите dev-сервер и откройте страницу. Первый завершившийся запрос выдаст ошибку.
Нажатие «Повторить» загрузит список. Перезагрузка страницы заново включает однократный
отказ. Параллельные запросы StrictMode получают одинаковый результат. Для обычного режима удалите
переменную или задайте `false`, затем перезапустите сервер. Файл `.env.local` игнорируется Git.

## Структура и решения

```text
src/
  main.tsx                         # React-точка входа
  App.tsx                          # корень: AppLayout → Dashboard
  api/modules/dashboard/
    interfaces/index.ts            # IRun, IRunStatus; модель из ТЗ
    mocks.ts                       # локальный набор запусков
    index.ts                       # getRuns(): Promise<IRun[]>
  components/
    shared/                        # button, icon, link
    composite/                     # feedback-state, modal
    layout/app-layout/             # оболочка и навигация
  views/dashboard/
    index.tsx                      # сборка основной страницы
    components/                    # список, фильтры, статус, диалог, skeleton
    hooks/useDashboard.ts          # запрос, условия, URL и выбранный запуск
    interfaces/index.ts            # типы условий и состояния запроса
    utils/                         # поиск, сортировка, URL, форматирование
    constants/                     # подписи и варианты условий
  styles/                          # глобальные стили и CSS-токены
  test/setup.ts                    # окружение React Testing Library
```

React + TypeScript + Vite; оформление на SCSS Modules. Состояние хранится в React hooks,
URL управляется через URLSearchParams и History API. Список вычисляется из исходных
данных без дублирования состояния. Флаг актуальности эффекта исключает обновление
состояния после размонтирования; сам mock-таймер не отменяется.
Общий Modal использует нативный `dialog` и получает открытие, обработчик закрытия,
тексты блоков, список кнопок и children через props. Содержимое запуска формирует RunDetailsModal.
Логи отображаются как текст. Для объединения CSS-классов используется classnames.
Tailwind, UI-библиотеки, MobX и роутер не подключены.

Компоненты лежат в отдельных папках с именами через дефисы: `run-details-modal/index.tsx`.
Собственные стили находятся рядом: `run-details-modal/run-details-modal.module.scss`.
Ошибка и пустой результат — отдельные компоненты, использующие общее оформление FeedbackState.

- [AI_LOG](AI_LOG.md) — краткое описание работы с AI.

## Проверки

25 тестов Vitest / React Testing Library проверяют фильтрацию, поиск и их сочетание,
сортировку, URL, открытие и закрытие деталей, необязательные поля, пустое состояние,
ошибку/повтор, StrictMode, игнорирование устаревшего ответа и независимость mock-данных.

Дополнительно в Chromium проверены ширины 360/768/1024/1440 px без горизонтального
переполнения, диалог и клавиатура, Back/Forward и перезагрузка ссылки, сценарий отказа
реального mock-сервиса, reduced motion и отсутствие ошибок в консоли.
Браузерная проверка использовала инструменты окружения и не добавляет зависимостей проекта.
Линтеры, TypeScript, форматирование и production-сборка проходят.

Для ручной проверки: совместите статус Running с поиском `web`, откройте результат,
закройте Escape, выберите сортировку, перезагрузите ссылку и проверьте Back/Forward.
Введите несуществующий запрос и сбросьте условия. Ошибку проверьте по инструкции выше.

`npm audit --omit=dev` не обнаружил runtime-уязвимостей. Полный аудит при подготовке
окружения выявил 10 moderate-предупреждений в цепочке ESLint/typescript-eslint из-за
minimatch. Несовместимые overrides и принудительные понижения версий не применялись.
